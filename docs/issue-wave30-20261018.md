# Formatter parsing/roundtrip regression contract — draft 2026-10-18

Issues #60 (sealed/non-sealed/final class headers) and #71 (nested ternary inherited false-arm shorthand).

## Sealed header test corpus (#60)
Accepted only when parser feature is enabled:
```ores
define sealed class Parent permits Child as end
define non-sealed class Child extends Parent as end
define final class Leaf as end
define pub abstract sealed class Root<T> permits pkg.Sub as end
```
All modifier order, permit targets, generic parameters and comments must round-trip identically under format → parse → format. Reject contradictory `sealed non-sealed`, duplicated modifiers, invalid `nonsealed`, permits on unrelated actor kinds, and accidental reformats of field-level `final const`.

## Ternary inheritance corpus (#71)
- `a ? (b ? 3) : fallback()` is shorthand only for the **parenthesized direct true-arm**; its expanded semantic equivalent is `a ? (b ? 3 : fallback()) : fallback()`.
- `a ? (b ? (c ? 3)) : 0` inherits the complete nearest enclosing false-arm expression transitively.
- `a ? (b ? 3 : 5) : 0` remains unchanged.
- `a ? 1 : b ? 2 : 3` remains right-associative, without implicit inheritance.
- `a ? x`, `a ? x : (b ? y)`, `a ? f(b ? y) : z`, `a ? ((b ? y)+1) : z` are invalid, never silently repaired by formatting.
- Comments and literal `?`/`:` characters must not change token identity.
- Postfix `value?` propagation is a separate grammar production and cannot be mistaken for incomplete ternary syntax.

**Release requirement:** parse-format-parse AST equivalence from canonical Java grammar and idempotence in Rust; syntax not yet supported must remain gated. This branch stages acceptance cases only, not a parser implementation or green CI claim.
